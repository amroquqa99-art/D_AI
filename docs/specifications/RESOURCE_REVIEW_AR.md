# مراجعة أولية لموارد المالك

التاريخ: 2026-10-19، Asia/Gaza. النطاق: فتح صفحات الروابط، قراءة أوصافها ومقاطع محددة، ومقارنتها بالنسخة المحلية من D_AI. لا تثبيت أو تفعيل أو تنزيل تبعيات أو تشغيل شيفرة خارجية في هذه الجولة. هذه المراجعة ليست تدقيقًا كاملًا للرخص أو الأمن أو التوافق أو جودة كل مشروع.

## دلالات الحالة

- «صفحة متاحة»: أمكن فتح الصفحة والتعرف على دورها العام؛ ليست حالة اعتماد أو إثبات تشغيل.
- «محتوى محدود»: الصفحة قابلة للفتح لكن النص المستخرج غير كافٍ لتقييم تفاصيلها.
- «تعذر فتح المجلد»: لا يعني أن المشروع غير موجود؛ قد يتوفر ملفه المباشر.
- مصدر معرفي أو معرض أو قالب أو مكتبة تنفيذ أو مهارة أو MCP ليست أشياء متكافئة. لكل منها طريقة تبنٍّ واختبار تناسبه.

## ملاحظات تمنع اعتماد استنتاجات غير مثبتة

1. غياب SPDX أو حقل `origin` ليس وحده دليلًا على غياب ترخيص أو مخالفة حقوق. يجب فحص الرخصة المنطبقة وملفات الإشعار والمصدر والتعديلات لكل مكوّن مختار. نسبة 32.5% في السجل المحلي تصنيف بيانات وصفية، لا نتيجة تدقيق حقوق مكتمل. [GitHub: تحديد الترخيص](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository).
2. ملف `frontend-design` الخام المفتوح يحيل صراحة إلى `LICENSE.txt`. الوصف السابق «بلا SPDX، إذن أنماط فقط» لا يكفي لحسم طريقة استخدامه؛ النص المحال إليه ما زال يحتاج مراجعة تخص التبني.
3. قرأت محليًا `token-budget-advisor` من ECC: يضبط عمق/طول الجواب بتقديرات. لا يثبت قياس تكلفة فعلية، ولا سقفًا مركزيًا، ولا جدولة موارد أو ضبط عدد الوكلاء. لا يُعتمد بديلًا لمنظومة ميزانيات D_AI.
4. قرأت محليًا `agent-architecture-audit`: يثير أسئلة عن تضارب التعليمات وتلوث الذاكرة والأدوات وإعادة المحاولة. فائدته المقترحة تشخيصية، ولم ينفذ تدقيقًا فعليًا لـD_AI في هذه الجولة.
5. كثرة الأدوات لا تثبت تحسن الجودة، وتكرار مهارات متشابهة قد يزيد التضارب. إثبات التبني المقترح: مهمة قبل الدمج وبعده، بمدخلات ومعيار قبول وموارد قابلة للمقارنة، مع تسجيل سبب التحسن أو التراجع.
6. لا مصدر من هذه القائمة يتحول تلقائيًا إلى مكوّن نشط أو تعليمات حاكمة لهذه الجلسة. لم تُشغّل مُثبّتاته.

## بحث إضافي في التنسيق — مرجع تصميم، وليس قرار تبعية

- [LangGraph: workflows and agents](https://docs.langchain.com/oss/python/langgraph/workflows-agents): يعرض التوجيه والتوازي وتفكيك العمل الديناميكي والتقييم والتحسين. يفيد مقارنة أنماط تركيب المسارات، دون إلزام D_AI بإطار تشغيل جديد.
- [A2A](https://a2a-protocol.org/latest/specification/): مرجع للتعاون عبر أنظمة مختلفة، مع المهام والرسائل والمخرجات والحالات الطويلة. الاتصال بين الوكلاء لا يحقق وحده ذاكرة مشتركة.
- [MCP](https://modelcontextprotocol.io/docs/getting-started/intro): مرجع وصل الأدوات والموارد؛ وجود خادم مشترك لا يثبت تنسيق ملكية المهام أو مشاركة حالة المحادثات بين البيئات.
- تعذر فتح صفحة Letta ومسار فرق AutoGen المحددين في هذه الجولة؛ لا تُنسب لهما نتائج تفصيلية هنا.

## عقد التبني المقترح

لكل مكوّن: المشكلة التي يحلها، ما يتكرر مع الموجود، موضع الاندماج، المصدر والنسخة والرخصة، متطلبات التشغيل، أثر السياق والموارد، توفيق التعليمات، المدخلات والمخرجات، التعامل مع الفشل، اختبار قبول مجال حقيقي، التحديث والرجوع. تعتمد الحزمة بعد تحقق المسار الفعلي، ويظل محتواها غير المطلوب خارج سياق المهمة.
