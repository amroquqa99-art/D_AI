# D_AI engineering

The owner goal is the complete, usable, publishable D_AI in this directory. The current release is 0.1: it is a foundation release, not V1. Do not redefine completion as a scaffold, prompt pack, core-only release, compatibility layer, or passing unit suite. Do not push, publish, purchase, renew subscriptions, or change the owner's global host configuration without applicable authorization.

Read `docs/specifications/PRD_AR.md`, `docs/specifications/OWNER_DECISIONS_AR.md`, and `docs/IMPLEMENTATION_STATE.md` before substantive work. The current owner's direct decisions override historical constraints such as OpenCode-only execution or one-level delegation. Preserve the scope and acceptance requirements across turns.

Source is on exFAT. Keep virtual environments, dependencies requiring symlinks, private data, credentials, databases and native locks on a Linux filesystem. The delivered source and supported setup commands must live here and be relocatable. Never commit credentials or private session data.

Use host-owned model calls and authentication for OpenCode and pi; don't introduce a direct provider API or paid fallback silently. Respect per-project model and budget authorization. Never print authentication material.

Every capability must have runtime integration and meaningful acceptance evidence. Record actual commands, versions, failures and outstanding gates. Scripted transport fixtures are not live inference; schema checks are not professional quality; rendering success is not motion quality. Never set a release gate to pass merely by editing a manifest or self-grading output.

Preserve unrelated work and imported material. Give each responsibility one clear owner; keep modules bounded and test behavior, concurrency, crash recovery and authorization boundaries. Maintain the continuation checkpoint at meaningful phase boundaries. The goal remains active until all requirements are proved from current state.
