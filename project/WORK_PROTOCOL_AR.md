# بروتوكول تنفيذ واستمرارية D_AI

## الهدف

يضمن هذا البروتوكول أن كل مهمة تترك المستودع في حالة مفهومة وقابلة للاستئناف والرجوع، وأن حالة الميزات تعكس أدلة تشغيل حقيقية.

## دورة المهمة

1. اختر بندًا جاهزًا من `IMPLEMENTATION_PLAN_AR.md` واربطه بـP-item أو risk/ADR واضح.
2. حدّث `PROJECT_STATE.md`: انقل المهمة إلى «ما يجري الآن»، اذكر المالك والفرع والنتيجة المتوقعة.
3. أنشئ branch قصيرًا وworktree منفصلًا عند وجود أكثر من عامل. لا يعمل عاملان على المسارات نفسها دون تنسيق صريح.
4. اقرأ `AGENTS.md` الأقرب لكل مسار، وعقود Harness ذات الصلة، قبل التعديل.
5. نفّذ أصغر vertical change يمر عبر runtime الحقيقي. لا يُغلق بند بوجود class أو UI أو mock فقط.
6. شغّل الاختبارات المتناسبة مع السطح المتغير وسجل الأوامر والنتائج الفعلية.
7. حدّث الوثائق و`HARNESS_DELTA.md` وFeature Matrix وADRs عند الحاجة.
8. حدّث `PROJECT_STATE.md` في نفس commit: المنجز، الجاري، غير المبدوء، blockers، tests، live مقابل fixture، والخطوة التالية.
9. أنشئ checkpoint غير متغير في `project/checkpoints/` عند إغلاق milestone أو تغيير معماري أو تسليم بين نماذج.
10. افتح PR، راجع diff، وتأكد أن CI يطابق Definition of Done قبل الدمج.

## صيغة checkpoint

اسم الملف: `YYYY-MM-DD_<milestone>_<short-commit-or-sequence>.md`.

يحتوي checkpoint على: الهدف، الملفات/commits، السلوك المثبت، الاختبارات ونتائجها، التكاملات الحية والـfixtures، migrations، القرارات، المخاطر الأمنية، القيود، وحزمة الاستئناف التالية. لا تُعدّل checkpoints القديمة؛ التصحيح يضاف في ملف أحدث ويرتبط بالسابق.

## Git وGitHub

- المستودع الخاص هو `origin`، والمصدر الرسمي read-only هو `upstream`.
- `main` محمي بعد تفعيل إعدادات GitHub؛ التغييرات تدخل عبر PR وفروع قصيرة.
- أمثلة الفروع: `phase/m1-reality-check`, `feat/p2-system-registry`, `fix/scheduler-lease-recovery`, `docs/adr-policy-engine`.
- commits ذرية برسائل Conventional Commits، مع فصل التغييرات المستقلة.
- تُستخدم tags للإصدارات وbaseline المعروف، وتكون artifacts والإصدارات موقعة عندما تجهز سلسلة الإصدار.
- لا تُخزن datasets أو models أو evidence أو backups أو أسرار في Git. تحفظ artifacts الكبيرة في مخزن مخصص مع hashes وlineage.
- أي مزامنة من upstream تكون مقصودة عبر branch/PR، ولا يوجد auto-merge.

## حالات العمل وحقيقة الميزة

حالة backlog مستقلة عن حالة نضج الميزة: `NOT_STARTED`, `READY`, `IN_PROGRESS`, `BLOCKED`, `IN_REVIEW`, `DONE`.

حالة نضج الميزة الملزمة حاليًا وفق `docs/PRODUCT_SPEC.md`:

- `FOUNDATION`: العقود أو البنية الأساسية موجودة لكنها لا تحقق رحلة مستخدم كاملة.
- `IMPLEMENTED`: السلوك الداخلي موجود ومثبت ضمن حدوده المعلنة.
- `INTEGRATED`: المسار متصل بالـruntime والتخزين والواجهة المناسبة.
- `VERIFIED`: اجتاز acceptance المعلن بأدلة محفوظة في بيئة محددة.

`NOT_STARTED` يعني غياب التنفيذ. غياب credentials أو provider حي يسجل `LIVE_INTEGRATION_BLOCKED` كسبب حظر مستقل، ولا يُستخدم كحالة نضج بديلة. قاموس الحزمة الأحدث وانتقالاته مسجلان في D-006 ولا يطبقان قبل قرار وترحيل صريحين. لا تستخدم كلمة Done لميزة لم تصل إلى معيار المهمة المرتبط بها.

## Definition of Done

- البند مرتبط بقبول أو issue واضح.
- السلوك يمر عبر مسار runtime حقيقي؛ الـfixture موسوم ولا يُعرض كتثبت حي.
- اختبارات السلوك والفشل والاسترداد المناسبة نجحت وسجلت.
- auth/policy/privacy/audit وتهديدات الإدخال غير الموثوق روجعت بحسب الخطر.
- migrations وrollback/forward recovery موثقة ومختبرة عندما تتأثر البيانات.
- health/metrics/errors موجودة عندما يضيف التغيير عملية تشغيلية.
- الواجهة تعرض state الخادم الحقيقي وحالات loading/empty/error/blocked.
- العربية والإنجليزية والوصولية تختبران عند تغيير واجهة.
- لا أسرار أو بيانات حقيقية حساسة في Git أو logs أو fixtures.
- `PROJECT_STATE.md` والوثائق وFeature Matrix محدثة.
- يمكن لمطور آخر الاستئناف من fresh clone.

## قواعد الوكلاء المتعددين

- قائد واحد يملك الخطة والدمج والحالة الحالية.
- كل وكيل يملك task محددة ومسارات متوقعة ونتيجة قبول.
- العمل المتوازي يستخدم worktrees وفروعًا منفصلة؛ مشاركة cwd المباشرة لا تعطي عزلًا.
- المراجعة الأمنية والمعمارية لا ينفذها نفس العامل الذي كتب التغيير الحساس وحده.
- لا يعتمد المشروع على ذاكرة المحادثة؛ كل قرار دائم يذهب إلى ADR أو ملف المشروع المناسب.

## محتوى لا يدخل ملف الحالة

لا يضاف إلى `PROJECT_STATE.md` أو checkpoints أي token أو API key أو prompt حساس أو بيانات عميل/دليل أو تفاصيل ثغرة قابلة للاستغلال. استخدم IDs وروابط artifacts محمية ووصفًا محدودًا.
