# D_AI Build Pack v2

هذا الباك هو المرجع التنفيذي المعتمد لبناء D_AI وفق الرؤية الحالية الكاملة.

## الملفات
1. `01_LOCKED_SPECIFICATION_AR.md` — المواصفة المقفلة للمنتج والقرارات غير القابلة للتأويل.
2. `02_SYSTEMS_CONTRACTS_AR.md` — تعريف الأنظمة الستة، حدودها، تكاملها ومخرجاتها.
3. `03_CORE_PLATFORM_CAPABILITIES_AR.md` — طبقات المنصة المشتركة والنواة المحلية والذاكرة والوكلاء والصلاحيات.
4. `04_ACCEPTANCE_MATRIX_AR.md` — معايير القبول العملية لكل مرحلة وكل نظام.
5. `05_MASTER_BUILD_PROMPT_AR.md` — البرومت التنفيذي الرئيسي لوكيل البرمجة/الفريق الهندسي.

## قاعدة الاستخدام
- ابدأ دائمًا من المصدر الحقيقي لـ DeepSeek Harness ثم ابنِ D_AI داخله كـ fork مستقل قابل للتطوير.
- لا تعتبر أي ميزة منفذة لمجرد وجود كلاس أو واجهة أو mock. الميزة تعتبر منفذة فقط إذا كانت مربوطة بمسار runtime حقيقي، مخزنة بحالة دائمة، ظاهرة في الواجهة، ومختبرة.
- كل نظام هو مكوّن أولي First-Class داخل المنصة، وليس Prompt منفصلًا.
- الأنظمة الستة الحالية: التحقيق، البحث العلمي، المستثمر، الأمن السيبراني، العمليات والاستخبارات، الابتكار والاكتشاف.
- النواة الذكية المحلية مكوّن مركزي من المنتج وليست Roadmap جانبية.
- كل الصلاحيات الحساسة تُفرض تقنيًا عبر runtime policy وليس عبر تعليمات نصية فقط.
- أي ميزة غير جاهزة بصدق يجب وسمها بوضوح: FOUNDATION / PARTIAL / INTEGRATED / TESTED / LIVE-VERIFIED.

## الهدف التنفيذي المختصر
D_AI هو بيئة تشغيل ذكاء اصطناعي متعددة الأنظمة، مخصصة للمهام العميقة طويلة الأمد، تستخدم وكلاء متعددين، ذاكرة مستمرة، أدوات، أدلة ومصادر، رسوم معرفة، صلاحيات مرنة، وموديلات محلية/سحابية، مع نواة محلية متخصصة تتطور تدريجيًا من بيانات التشغيل المصرح بها.
