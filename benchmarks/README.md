# مقاييس D_AI — بنية الحالة

كل حالة **مهمة حقيقية** لها فاحص حتمي يُخرج رقماً. لا نموذج في الفاحص ولا شبكة.

## بنية الحالة

```
benchmarks/cases/<ID>-<slug>/
  meta.json     هوية الحالة والمقياس
  task.md       نصّ المهمة، يُمرَّر للوكيل **حرفياً**
  workspace/    الملفات الابتدائية (تُنسخ إلى مساحة كل ذراع)
  check.py      الفاحص الحتمي
```

## `meta.json`

```json
{
  "id": "B01-slice-sum",
  "name": "إصلاح خلل في جمع شريحة",
  "metric": "اختبارات ناجحة / الإجمالي",
  "unit": "tests",
  "threshold": 1.0,
  "why": "يقيس: هل يقرأ الوكيل الكود، يجد الخلل، يصحّحه، ويتحقق؟"
}
```

## `check.py`

يُنفَّذ في مساحة العمل **بعد** انتهاء الجلسة، ويُقبل `argv[1]` = مسار المساحة.
**يجب** أن يطبع على stdout كائن JSON واحداً في السطر الأخير:

```json
{"passed": true, "score": 1.0, "metrics": {"tests_passed": 6, "tests_total": 6}, "detail": "..."}
```

- `score`: بين 0 و1 — **هذا هو الرقم القابل للمقارنة**.
- `metrics`: العدّادات الخام (اختبارات ناجحة، صفوف مُطابقة، روابط متحقَّقة…).
- `detail`: جملة واحدة تشرح الرقم.
- `passed`: `score >= threshold`.

**قواعد الفاحص:**
- حتمي تماماً: نفس المساحة تعطي نفس الرقم.
- لا يستدعي نموذجاً، ولا يفتح شبكة، ولا يعتمد على ساعة.
- لا يثق بما يقوله الوكيل: **يقيس الملفات نفسها** (يشغّل الاختبارات، يقرأ JSON، يطابق النص).
- يعامل فشل الوكيل كـ`score: 0` بصمت: لا استثناء، لا中止.
- يحدّ وقت التشغيل (استعمل `subprocess` بمهلة قصيرة).

## ما الذي يجعل الحالة «حقيقية»

- مهمة لها **نتيجة قابلة للفحص آلياً**: برنامج يُنفَّذ، أو ملف يُقرأ، أو قيمة تُحسب.
- لا تُحلّ بالتخمين: الفاحص يفحص العمل لا الإجابة.
- **الفخاخ مقصودة**: في كل حالة شرط أو حدّ يَحذفorc途径 التحايل (استخدام أداة ممنوعة، نسبة زائفة، اقتباس بلا مصدر). الفخاخ التي تُكتشف تُسجَّل في `metrics` تحت اسم واضح.

## التشغيل

```bash
python scripts/bench_run.py --model opencode/<model-id> --out benchmarks/results/<stamp>
python scripts/bench_run.py --model opencode/<model-id> --arm system --only B01-slice-sum
```

الناتج: `results.json` (الآلي) و`BENCH.md` (جدول بأرقام).
